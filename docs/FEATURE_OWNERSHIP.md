# Oblivion feature ownership inventory

This inventory distinguishes the product surface from inherited technology and provider-owned data. It is based on the current source tree; it does not certify third-party licensing or redistribution rights. See `THIRD_PARTY_NOTICES.md` and `docs/RELEASE_READINESS.md` for open provenance blockers.

| Area | Classification | Current implementation / boundary | M14 treatment |
| --- | --- | --- | --- |
| Launcher dashboard and local launch orchestration | Oblivion-owned, inherited implementation | `MainActivity`, `VersionManager`, `MinecraftLauncher`, `MinecraftRuntimePreparer`, and `GamePackageManager` discover and launch the installed official Minecraft app. | Retained. Native loader diagnostics are improved; game APK/assets and launch method are unchanged. |
| Profiles and instances | Oblivion-owned, inherited implementation | Existing `GameVersion` and version/profile storage back the Instances UI. | Retained; profile identifiers and storage layout are unchanged. |
| Add-On, resource/behavior pack, and world management | Oblivion-owned local feature | Existing `ContentManagementActivity`, `ContentImporter`, `ResourcePackManager`, and `WorldManager` operate on local Bedrock content. | Retained and available without remote services. |
| External mods and in-game native mods | Legacy feature requiring adaptation and trust review | `ModManager`, `ModNativeLoader`, catalog installation, and `System.load` support native extensions. | Existing local/mod-SDK behavior retained. Catalog native publisher identity and arbitrary native code trust remain unresolved; do not treat catalog content as verified. |
| Package/modpack manager | Third-party integration requiring attribution | `PackagesActivity`/`PackageActivity`, `Catalog`, `PackageService`, `PackageEngine`, `Manifest`, `LocalSources`, and `LeviLamina` follow the `lip` package format and query the `levimc.org` catalog/version database. The package identity and source are provider/technology-specific, not an Oblivion-owned catalog. | Existing package IDs, `lip.toml`/legacy archive compatibility, workspace state, installation plan, and LeviLamina integration are retained. UI copy identifies Oblivion while catalog/provider identity remains attributable. |
| Microsoft/Xbox/Minecraft account | Third-party authentication integration | `MsftAuthManager`, `MsftAccountStore`, and `XalExporter` handle official account flow and existing local serialization/export. | Kept separate from any future Oblivion Account. Existing IDs, files, and authentication behavior are unchanged. Plaintext serialization-layer and upstream API risks remain documented. |
| CurseForge catalog | Third-party provider integration | Existing provider-specific catalog API and content restrictions. | Release/Beta remain disabled without authorized configuration; local content does not depend on it. |
| News and notifications | Legacy feature requiring provider adaptation | `NewsRepository`, bundled JSON, and Firebase Messaging previously consumed the upstream LeviLauncher feed/topic. | Bundled stale announcements are removed; the feed URL now targets the Oblivion repository. Prior cache is ignored unless marked as Oblivion data. FCM delivery still depends on inherited Firebase/topic configuration and is not verified as an Oblivion-operated service. |
| App updates | Unavailable / replacement plan required | `GithubReleaseUpdater` has no current call site. The active Settings link opens the project repository; user-facing copy says Oblivion release updates are not configured. | No upstream APK is advertised or installed. A future update service needs reviewed Oblivion-owned releases, provenance validation, and explicit release controls. |
| AI assistant | Open-source UI/provider contract; real provider unavailable | Assistant UI and provider boundary exist, but no backend is configured. | Retained as unavailable/offline; no fake responses or credentials added. |
| Oblivion account, cloud sync, premium | Unavailable; architecture only | `docs/CLOUD_ACCOUNT_ARCHITECTURE.md` defines future boundaries. | No fake login, backup, entitlement, payment, or synchronization introduced. |
| Settings, language, personalization | Oblivion-owned local feature | Existing preference-backed settings and theme/language managers. | English is the first-install default. Explicit language choices and existing preference key remain supported. |
| Pojav Controls | Third-party integration | Existing `:pojav_controls` module and licensing obligations. | Retained; no product renaming of upstream library identity. |
| Crash reporting and Firebase services | Third-party service integration | xCrash local capture/recovery plus optional Firebase Crashlytics/Messaging adapters. | Local recovery is independent. Firebase credentials/configuration are not introduced by M14. |

## M14 ownership boundary

Visible application-owned copy now says Oblivion. Names such as Microsoft, Xbox, CurseForge, LeviLamina, `lip`, LiteLDev, LeviMC, and original LeviLauncher authors remain when they identify a real provider, upstream author, protocol, or legacy storage location. Those labels are not claims of Oblivion ownership. The About screen links to `M4Lych/nexus-bedrock-android` and retains a separate upstream identity link.
